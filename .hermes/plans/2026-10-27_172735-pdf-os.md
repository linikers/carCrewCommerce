# PDF da Ordem de Serviço — plano de implementação

> **Para executar:** vai junto no PR **#156** (`feat/os-fluxo-completo`), como commit novo na mesma branch.

**Objetivo:** gerar o PDF da OS (orçamento e ordem de serviço) para imprimir, assinar e enviar ao cliente.

**Hoje não existe nada disso.** Verificado em 27/10:

```
package.json   → nenhuma lib de PDF (sem puppeteer, jspdf, pdfkit, @react-pdf)
src/           → nenhuma rota ou componente que gere PDF
```

A única menção é o texto "Baixar o XML e o DANFE em PDF" na tela de módulo em breve do fiscal — que é outra coisa (NF-e).

---

## Decisão técnica: `@react-pdf/renderer` no servidor

| Opção | Roda na Vercel? | Prós | Contras |
|---|---|---|---|
| **`@react-pdf/renderer`** | sim (Node runtime) | gera arquivo de verdade, layout em componentes, sem browser | +~1,5 MB de bundle, fontes padrão só Helvetica |
| `pdfkit` | sim | leve, controle fino | API imperativa (desenhar linha por linha), mais código |
| Puppeteer / Playwright | **não** (sem Chromium no serverless) | HTML/CSS reaproveitado | precisa de container próprio — não vale hoje |
| HTML + `@media print` | sim, no navegador | zero dependência, entrega hoje | não gera arquivo no servidor; depende do "salvar como PDF" do usuário |

**Escolha:** `@react-pdf/renderer` com runtime Node, duas rotas (interna e pública) e um componente único de documento.

Fase 2 (fora deste plano): botão de impressão direta (`window.print()`) usando o mesmo conteúdo, se ele quiser imprimir sem baixar.

## Estrutura

```
src/modules/os/pdf/
  DocumentoOS.tsx        # layout A4 do documento (puro, sem Prisma)
  gerar.ts               # dados da OS -> props do documento -> Buffer

src/app/api/admin/os/[id]/pdf/route.ts    # autenticado, inclui custo e margem
src/app/api/orcamento/[token]/pdf/route.ts # público, sem custo interno
```

Regra de fronteira já usada no projeto: `pdf/` é UI de módulo, não importa outro módulo; os dados vêm por parâmetro.

## Tarefas

### Tarefa 1 — Instalar e provar que roda no build

```bash
npm install @react-pdf/renderer
```
Criar `src/modules/os/pdf/DocumentoOS.tsx` com um documento mínimo (título + um texto).

**Verificação:** `npx next build` passa e o bundle da rota não estoura o limite da Vercel (função < 250 MB; deve ficar em ~2 MB).

### Tarefa 2 — Documento completo

Implementar `DocumentoOS.tsx` com as seções acima, recebendo:

```ts
interface PropsDocumentoOS {
  ordem: { id, criadoEm, prazo, status, cliente*, veiculo, placa, km, descricaoProblema, observacoes, total*, aprovadoEm };
  itens: { tipo, descricao, quantidade, valorUnit, total, custo? }[];
  incluirCusto: boolean;
}
```

Fonte Helvetica (padrão, sem `Font.register` — evitar `fs` no serverless).
A4 retrato, margem 32 pt, tabela com cabeçalho repetido.

**Verificação:** gerar com dados de fixture e abrir o PDF.

### Tarefa 3 — `gerar.ts`

```ts
export async function gerarPdfOS(props: PropsDocumentoOS): Promise<Buffer>
```
Usa `renderToBuffer` de `@react-pdf/renderer`.

**Verificação:** script temporário que grava `/tmp/os.pdf` e roda `pdftotext` conferindo nome do cliente, placa e total.

### Tarefa 4 — Rota interna

`GET /api/admin/os/[id]/pdf`
- `requireAdmin()` + `exigirModulo("os")` (mesmo padrão das outras rotas)
- `Content-Type: application/pdf`, `Content-Disposition: inline; filename="OS-<id>.pdf"`
- `export const runtime = "nodejs"` (obrigatório: `renderToBuffer` não roda no edge)

**Verificação:** `curl` com cookie de admin → `200`, `%PDF-1.3` no começo, ~30–60 KB.

### Tarefa 5 — Rota pública (cliente)

`GET /api/orcamento/[token]/pdf` — sem login, **sem custo interno**, só se o token existir.
Mesma validação de existência usada em `lerOrcamentoPublico`.

**Verificação:** abrir sem cookie → 200; token inválido → 404; conferir com `pdftotext` que não aparece "custo".

### Tarefa 6 — Botões na tela

Em `OSDetalhe.tsx`:
- botão **PDF** ao lado de "Editar dados" → abre `/api/admin/os/<id>/pdf` em nova aba
- no diálogo "Enviar orçamento", segundo botão: **PDF do orçamento** (link público)
- na página pública `/orcamento/[token]`, link "Baixar PDF"

## Riscos e decisões abertas

| Risco | Mitigação |
|---|---|
| Peso no bundle serverless | documento é o único import de `@react-pdf`; rota isolada |
| Fonte quebrada em produção | só Helvetica (embutida na lib), nada de `fs` |
| Custo interno vazar para o cliente | custo só entra com `incluirCusto: true`, e a rota pública nunca passa `true` — testar com `pdftotext` |
| Dados da empresa (CNPJ/endereço) não existem no sistema | perguntar; se não houver, sai só nome + telefone até cadastrarem |

**Perguntas para fechar antes de implementar:**
1. O PDF vai ter **logo** da Car Crew? (se sim: arquivo PNG em `public/`)
2. CNPJ e endereço entram no cabeçalho? (hoje não existem no banco)
3. O cliente pode **baixar o PDF** pelo link público, ou o PDF é só uso interno?

**Esforço estimado:** 6 tarefas, ~2 h de implementação + 30 min de revisão de layout.
